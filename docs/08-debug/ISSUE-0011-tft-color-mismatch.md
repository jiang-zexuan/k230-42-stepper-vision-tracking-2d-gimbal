# ISSUE-0011：ILI9341 TFT 纯色显示异常

## 状态

- 日期：2026-08-23
- 状态：已解决
- 分支：`feature/f407-p10-dual-axis-visual-tracking`
- 关联阶段：P10，F407 驱动 TFT 状态屏
- 原始现象：程序依次发送红、绿、蓝填屏，但屏幕实测显示为“蓝、紫、黄”。
- 最终现象：移植完整初始化后，屏幕依次正确显示红、绿、蓝。
- 最终结论：F407 侧 SPI 字节、DC、CS 和 RGB565 颜色常量均正确；根因是最小初始化不足以让当前 MSP2833/MSP2834 模块进入可正确显示的工作状态。

## 目标

把屏幕颜色异常从“猜接线、猜颜色格式”转化为可复现、可测量、可定位的问题，并保留完整证据，最终明确根因和修复方式。

## 现象与预期

启动测试代码依次调用：

```c
ILI9341_FillColor(ILI9341_COLOR_RED);
HAL_Delay(1000U);
ILI9341_FillColor(ILI9341_COLOR_GREEN);
HAL_Delay(1000U);
ILI9341_FillColor(ILI9341_COLOR_BLUE);
```

预期现象：红、绿、蓝各显示约 1 秒，最后保持蓝色。

实际现象：红、绿、蓝三个阶段均能改变画面，但颜色显示为蓝、紫、黄。

“画面能改变”说明屏幕并非完全没有响应；“颜色不对应”说明仍需区分像素格式、字节顺序、颜色排列和初始化状态。

  - 第 3.1 节：ILI9341 使用 16 bit RGB565 控制一个像素。

## 排查过程

### 1. 先确认能否构建和运行

- CubeMX 已加入 SPI1、PB3/PB4/PB5 和 TFT 控制 GPIO。
- Keil 构建结果：`0 Error(s), 0 Warning(s)`。
- 启动测试改为红、绿、蓝三色循环。

结论：问题不是工程无法编译，也不是程序没有执行填屏代码。

### 2. 先验证最小硬件链路

已确认 TFT 能显示稳定的整屏颜色，说明供电、背光、复位和部分 SPI 链路有效。没有直接把“出现颜色”当成“颜色格式正确”。

### 3. 使用逻辑分析仪脱离 TFT 测量 F407 输出

为避免线束限制，先拔下 TFT，只测 F407 引脚：

```text
逻辑分析仪 D0 -> F407 PB3 / SPI1_SCK
逻辑分析仪 D2 -> F407 PB5 / SPI1_MOSI
逻辑分析仪 D4 -> F407 PC13 / TFT_LCD_CS
逻辑分析仪 D6 -> F407 PA5 / TFT_LCD_DC
逻辑分析仪 GND -> F407 GND
```

SPI 解码设置：Mode 0、MSB First、8 bits、Enable Active Low、MOSI=D2、Clock=D0、Enable=D4；D6 单独观察 DC 电平。

第一次截图中把 D0 和 D2 选反，导致大量 `0xFF` 或 `0x00` 与 `99+ Error`。没有把错误解码结果当作固件错误，而是回到通道映射重新核对。

### 4. 导出并分析原始协议结果

证据文件：`C:\Users\a7864\Desktop\11.csv`

CSV 中已经确认：

```text
1.752423667 s : 0x3A
1.752449542 s : 0x55
1.752480417 s : 0x36
1.752506292 s : 0x48
1.752536708 s : 0x29
1.752909125 s : 0x2C
1.752941250 s : 0xF8
1.752943417 s : 0x00
3.098421583 s : 0x07
3.098423750 s : 0xE0
4.443868083 s : 0x1F
4.443870250 s : 0x00
```

对应解释：

```text
3A 55       设置 16 bit RGB565
36 48       设置扫描方向
29          开启显示
2C          开始写显存
F8 00       红色 RGB565
07 E0       绿色 RGB565
00 1F       蓝色 RGB565
```

结论：F407 的 SPI 时钟、片选和 MOSI 字节已经有直接波形证据，当前不能再把问题归因于“F407 没有发送数据”。

### 5. DC/RS 已确认

已通过逻辑分析仪确认：

- 发送 `0x3A` 命令时，D6 为低电平；
- 紧接着发送 `0x55` 参数时，D6 为高电平。

因此当前已排除 F407 侧的 SPI 通道映射、CS 片选和 DC/RS 命令数据切换错误。

### 6. 当前未决问题

仍需确认：

1. 屏幕实际控制器是否确实按 ILI9341V 的 16 bit 模式工作；
2. `0x3A=0x55` 是否被屏幕端正确接受；
3. 屏幕实际像素字节顺序和 RGB/BGR 排列是否与资料一致；
4. 是否需要完整官方 ILI9341 初始化序列，而不是当前最小初始化序列。

下一项实验是连接 TFT `SDO/MISO -> F407 PB4`，读取控制器 ID。资料库没有给出该模块的 ID 返回值，因此以实测为准。

## 这次排查体现的工程方法

1. **先描述现象，不直接命名根因**：记录“红绿蓝输入，屏幕显示蓝紫黄”，不直接写成“字节序错误”。
2. **先建立最小可复现测试**：用固定三色代替完整状态界面，减少变量。
3. **按链路分层定位**：构建 -> 供电/复位 -> GPIO 控制 -> SPI 时钟/片选 -> MOSI 字节 -> DC 命令/数据 -> 屏幕解释。
4. **一次只验证一个假设**：通道配置错误时先修解码，不同时修改颜色格式。
5. **用独立测量替代猜测**：屏幕拔掉后测 F407 输出，先把“发送端”和“接收端”分开。
6. **保留失败证据**：第一次 `0xFF/0x00` 解码结果也保留，因为它说明分析仪通道映射曾经错误。
7. **结论必须对应证据**：CSV 能证明 F407 发了 `3A 55` 和 RGB565 字节，但不能单独证明屏幕已经正确解释它们。

## 下一步实验

在修改屏幕初始化代码前，继续用逻辑分析仪放大 `0x3A/0x55` 所在时间段，核对 D6：

- `0x3A` 期间 D6 必须为低（命令）；
- `0x55` 期间 D6 必须为高（数据）。

若 D6 也正确，再测试完整 ILI9341 初始化序列或核对模块实际控制器；若 D6 错误，先修正 LCD_RS/DC 的 GPIO 控制。
