# ADR-0003：P10 视觉跟踪状态机

- 日期：2026-08-23
- 状态：已实施，实物验收待完成

## 背景

P09 已经可以根据 X 误差驱动水平轴，P10 又加入了 Y 误差、俯仰轴和 TFT/触摸界面。若只用 `target_present` 和两个速度变量，无法区分“正在找目标”“目标正在跟随”“目标已经稳定居中”“通信中断”和“安全条件异常”。

## 决策

在 `main.c` 中增加五态视觉状态机：

| 状态 | 进入条件 | 安全动作 | 屏幕颜色 |
| --- | --- | --- | --- |
| `SEARCH` | 未接管、关闭视觉或有效帧明确表示无目标 | 停止两轴 STEP | 蓝 |
| `TRACKING` | 有目标且 X/Y 任一误差超出死区 | 按当前比例速度驱动两轴 | 黄 |
| `LOCKED` | X/Y 同时进入死区并持续 500 ms | 停止两轴 STEP，保留状态提示 | 绿 |
| `LOST` | 超过 300 ms 没有有效 K230 结果 | 停止两轴 STEP | 橙 |
| `FAULT` | 位置未回中、俯仰未归零或下一步将越过软件限位 | 停止 STEP，释放 EN | 红 |

状态变化通过 USART1 输出一次 `VIS state=... reason=...`，TFT 顶部同步显示状态、X/Y 误差、两轴软件脉冲位置和速度目标。状态机仍运行在裸机主循环中，TIM3/TIM4 中断只负责 STEP 周期和位置累计。

## 原因

把“是否允许运动”和“为什么停止”集中到状态机，能够避免某一条通信、触摸或电机路径遗留上一帧速度，也让串口日志、屏幕和后续故障测试共享同一语义。500 ms 锁定判定使用 `HAL_GetTick()` 的毫秒时间基准，与现有非阻塞任务模型一致。

## 风险与待验证

- TFT 字库目前是有限英文/数字 5x7 点阵，状态英文可显示，中文字体仍待补充。
- TFT 采用局部刷新：标题只在启动时绘制，状态色块和固定宽度数值字段每 500 ms 覆盖一次；文字一行使用一笔 SPI 写入，避免“先清空 240x70 顶部区域再重画”的闪烁和大量小事务。若后续需要更高刷新率，再评估 DMA。
- 早期 P07/P10 记录中的俯仰 `±45°` 是阶段性安全范围；P12 最终方案已将俯仰软件限位调整为 `±90°`，仍须在实际机械装配中避免结构干涉。
