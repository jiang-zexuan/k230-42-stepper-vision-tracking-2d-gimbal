# P02：非阻塞定时任务台复盘

- 日期：2026-08-15
- 阶段状态：实测通过。
- 固件提交：`0afd250`。

## 本项目解决的问题

P01 的按键消抖使用了 `HAL_Delay(20)`。P02 将主循环组织为多个按周期到期的任务，使按键扫描、状态维护与心跳日志能够共同运行。

## 已实测的结果

| 项目 | 实测结果 |
| --- | --- |
| 10 ms 按键扫描 | 每 500 ms 心跳周期内扫描计数增加 50。 |
| 100 ms 状态任务 | 每 500 ms 心跳周期内状态计数增加 5。 |
| 500 ms 心跳 | 226 条 P02 格式样本的 `dt` 最小、最大、平均值均为 500 ms。 |
| 非阻塞消抖 | KEY0 事件发生时心跳持续输出；日志包含 6 条 `KEY0 pressed`。 |
| DS0 行为 | 用户现场确认短按或按住 KEY0 均只切换一次。 |

## 代码到意图

| 代码 | 它实现的意图 |
| --- | --- |
| `PeriodicTask` | 保存周期与上次执行时刻。 |
| `PeriodicTask_IsDue()` | 只有任务到期时才运行，随后立即回到主循环。 |
| `DebouncedButton` | 跨多次扫描保存按下状态，替代阻塞式等待。 |
| `t`、`dt` | 用日志直接测量心跳实际周期。 |

## 复习要点

1. 裸机多任务可由一个 `while (1)` 轮流调度多个到期条件实现。
2. `HAL_Delay()` 会停止当前执行流；状态机把等待拆散到多轮循环。
3. 任务频率不同不等于优先级不同；当前所有任务仍在同一个主循环中依次执行。

## 学习问答

### 为什么一个时钟可以管理多个定时任务？

`HAL_GetTick()` 只提供统一的当前毫秒数，不直接触发任何任务。每个 `PeriodicTask` 分别保存自己的 `period_ms` 和 `last_run_ms`，通过 `now_ms - last_run_ms >= period_ms` 独立判断自己是否到期。因此一个时间基准可以服务 10 ms、100 ms、500 ms 等多个不同周期的任务。

### P02 用到了什么状态机？

用了两个隐式状态机：

1. `PeriodicTask` 在“等待周期到达”和“任务到期后更新时刻”之间转换。
2. `DebouncedButton` 在“未按下”“检测到可能按下并等待 20 ms 稳定”“已确认按下，等待松开”之间转换。

它们用 `last_run_ms`、`previous_pressed`、`press_pending` 和 `press_started_ms` 保存状态，而不是使用显式的 `enum`。

### 为什么需要状态机？

很多嵌入式问题依赖过程而非某一瞬间：按键需要判断是否持续按下 20 ms，定时任务需要记住上一次执行时刻。状态机通过保存历史状态，让“当前输入 + 历史状态”决定下一步动作；它既能避免按住按键重复触发，也能避免用 `HAL_Delay()` 原地等待。
