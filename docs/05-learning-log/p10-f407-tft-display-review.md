## 复习要点

1. RGB565 颜色常量是标准值：`F800` 红、`07E0` 绿、`001F` 蓝。
2. 官方 STM32 示例的 16 位像素发送顺序是高字节先发、低字节后发。
3. “SPI 波形正确”只证明 F407 发得正确，不证明屏幕控制器已经完成正确初始化。
4. `TFT ID=00 00 00 0F` 不能直接证明型号错误；读回链路的可靠性需要模块资料保证。
5. 完整初始化序列是模块适配的一部分，不是可有可无的装饰代码。
6. 纯色诊断通过后，才能进入文字显示；先显示英文数字，再加入中文点阵，最后接入视觉状态。

## 触摸交互实测

已经完成以下链路：

1. 通过 `HAL_I2C_IsDeviceReady()` 确认 FT6336G 的 I2C 地址应答。
2. 通过 `HAL_I2C_Mem_Read()` 读取 `0x02` 和 `0x03~0x06`，获得触摸点数量与第一个触摸点原始坐标。
3. 实测当前显示为 180 度旋转，原始 X/Y 坐标均需反向：`screen_x=239-raw_x`、`screen_y=319-raw_y`。
4. 已实测四区域命中：左上、右上、左下、右下均能输出正确 `zone`。
5. 已实测触摸 UI 按下反色、松手恢复。
6. 已实测按钮按下沿动作：`MODE` 切换视觉跟踪、`TAKE` 切换接管、`STOP` 停止并清除位置有效性、`INFO` 读取电机状态。

## P10 双轴视觉状态机

已经把 P09 的水平跟踪扩展为双轴状态闭环。每次主循环根据接管开关、最近有效 K230 帧、目标存在、X/Y 死区、软件位置和限位方向计算一个唯一状态：`SEARCH`、`TRACKING`、`LOCKED`、`LOST` 或 `FAULT`。

已经把“目标进入死区”与“目标已经锁定”分开：进入死区先保持 `TRACKING`，连续 500 ms 没有离开死区才进入 `LOCKED`。`SEARCH`、`LOCKED`、`LOST`、`FAULT` 都停止视觉 STEP；`FAULT` 额外释放两轴 EN。状态变化只通过 USART1 输出一次，避免心跳日志刷屏。

TFT 顶部已增加状态块和三行运行数据：`X/Y` 为图像像素误差，`P/T` 为水平/俯仰软件脉冲位置，`V/W` 为两轴速度目标。底部原有四个触摸按钮继续保留，方便在同一页执行模式切换、接管、停止和状态查询。

### 状态转换速查

| 条件 | 状态 | 运动动作 |
| --- | --- | --- |
| 未接管、关闭视觉、无目标帧 | `SEARCH` | 停止两轴 |
| 有目标且任一误差超出 40 px 死区 | `TRACKING` | 按 X/Y 比例速度跟随 |
| X/Y 同时在死区内持续 500 ms | `LOCKED` | 停止两轴并显示绿色 |
| 300 ms 无有效帧 | `LOST` | 停止两轴并显示橙色 |
| 未回中、未归零或下一脉冲越界 | `FAULT` | 停止两轴、释放 EN、显示红色 |

本轮代码已具备实物验收条件，`SEARCH/TRACKING/LOCKED/LOST/FAULT` 的现场日志和误差 5% 指标仍待实测，不提前写成通过。

## 已问知识点与答案

- 为什么先轮询再中断：轮询便于先确认寄存器和坐标链路；正式版本再让 `CTP_INT` 只置位事件标志，I2C 读取仍放在主循环。
- 轮询是否浪费 MCU：当前 50 ms 一次、每次读取几个字节，对 F407 负载很小；中断化是后续降低空闲总线访问和提升响应的优化。
- 为什么 `chip_id=00` 不能直接判故障：`0xA0` 的默认值可能为 0，且当前识别寄存器读回值与资料默认值不一致，只能作为待验证诊断，不作为型号结论。

## 复习要点（P10 加速批次）

1. 状态机的价值是把“现在发生了什么”和“允许做什么”统一起来；同一状态同时驱动电机安全动作、屏幕颜色和串口解释。
2. `LOCKED` 不是一次误差为零，而是误差连续满足条件并经过时间确认，避免目标在边界抖动时误报锁定。
3. `LOST` 表示通信超时，`SEARCH` 表示通信仍在工作但暂时没有目标，两者都停机但原因不同。
