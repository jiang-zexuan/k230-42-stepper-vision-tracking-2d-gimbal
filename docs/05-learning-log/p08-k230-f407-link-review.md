## 这一步做了什么

已把 K230 的 `PV04` 文本结果通过专用通信口送入 F407 USART2。F407 使用 USART2 RX DMA 接收字节，DMA 空闲事件只表示“收到一段字节”，再由文本行累积器遇到 `LF` 后提交完整一行，最后交给视觉结果解析器。

已解析并记录目标是否存在、目标数量、目标中心 `cx/cy`，并以固定源图像 `1920x1080` 的中心 `(960,540)` 计算 `err_x/err_y`。随后加入水平轴速度目标计算：死区 40 px、比例 2 脉冲/px、最大速度 800 脉冲/s；当前只输出 `pan_speed`，尚未让视觉结果驱动电机。

已实测当前安装姿态的方向约定：目标在画面左侧时水平正方向有效，目标在画面右侧时水平负方向有效，因此控制器对图像 X 误差取反。屏幕显示可能是镜像的，控制依据始终是画面中的目标位置。

## 为什么要学

视觉跟踪不是“收到坐标就直接转电机”。必须先把连续 UART 字节还原成完整消息，再确认坐标含义、画面中心、死区、比例和方向映射。把通信、数学和执行机构分开验证，才能知道问题出在串口、解析器还是电机方向。

## 代码动作 -> 工程意图

| 代码动作 | 工程意图 | 大白话描述给 AI |
| --- | --- | --- |
| `HAL_UARTEx_ReceiveToIdle_DMA()` | 高效搬运 USART2 字节 | “让 DMA 收字节，空闲只做通知，不把通知当完整消息。” |
| `UartTextLineAccumulator_Consume()` | 处理半帧和 DMA 分段 | “把多次收到的片段拼起来，看到换行才交给解析器。” |
| `VisionTextResult_Parse()` | 将 ASCII 文本转成结构化结果 | “只接受固定 PV04 格式，字段不完整就报错。” |
| `VisionError_FromTarget()` | 计算目标相对画面中心的偏差 | “用目标中心减画面中心，右和下在图像坐标中为正。” |
| `VisualTrackController_HorizontalSpeed()` | 将偏差变成受限速度目标 | “小误差不动，大误差按比例动，速度不能超过上限。” |

## 关键 HAL 函数

| 函数 | 本课用途 |
| --- | --- |
| `HAL_UARTEx_ReceiveToIdle_DMA()` | 启动 USART2 DMA 接收并在空闲时回调。 |
| `HAL_UARTEx_RxEventCallback()` | 复制/消费 DMA 字节片段并重启接收。 |
| `HAL_GetTick()` | 为后续通信超时保护提供毫秒时间基准。 |
| `HAL_UART_Transmit()` | 通过 USART1 输出每秒诊断汇总。 |

## 复习要点

1. DMA 的空闲回调给出的是“本次收到多少字节”，不是协议意义上的一帧。
2. 文本协议用 `CRLF/LF` 界定行；二进制协议必须使用长度、帧头和校验等边界。
3. 图像坐标正负与机械轴正负不是天然相同，必须结合安装姿态实测。
4. 无目标时应输出停止命令，不能沿用上一帧速度。
5. 当前 `pan_speed` 仍是抽象命令，视觉闭环电机执行属于下一步实测。
