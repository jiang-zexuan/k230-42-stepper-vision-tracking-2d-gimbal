## 这次做了什么

我把 K230 的视觉目标从官方人脸例程切换为自定义训练模型，并让模型结果继续通过 K230 专用 TX/RX/5V/GND 接口发送给 F407。F407 仍按文本帧解析目标状态、目标中心坐标和误差，再交给双轴视觉跟踪控制器。

我把 TFT 主页收敛为运行状态界面：保留 `PanView` 标题、状态显示、运行时间、目标 X/Y 距离、启动/停止按钮和 `Designed by JZX` 页脚；同时加入四种主题色并支持触摸切换。按钮按下时改变边框和填充反馈，避免把整屏内容反复清空。

我把俯仰软件限位从 ±45° 调整为 ±90°，水平轴继续保留 ±90°。启动仍要求人工回中，停止后清除位置有效标志，下一次启动必须重新建立零点。

我保留了 PID 跟踪、速度斜率限制和锁定滞回。锁定进入时间调整为 250 ms；针对目标到位后偶发抖动，将锁定退出死区从 ±50 像素小幅放宽到 ±60 像素。普通跟踪死区仍为 30 像素，避免整体灵敏度下降。

我还补充了 K230 USART2 DMA 启动诊断：记录启动尝试、成功次数、接收事件、HAL 状态和 UART 错误；DMA 重启失败时设置待恢复标志，由应用上下文持续重试，避免 K230 晚上电时第一次通信失效。

## 为什么锁定后会抖动

视觉框不是绝对稳定的。即使目标没有移动，检测框中心也可能在几个像素到几十个像素之间变化。如果锁定状态只允许很窄的误差范围，误差一越界就会重新启动电机；电机启动后误差又回到范围内，于是状态在 `LOCKED` 和 `TRACKING` 之间来回切换。

这里使用的是滞回思想：进入锁定使用普通死区，离开锁定使用更宽的退出死区。这样小幅测量抖动不会触发电机重新启动，但真正偏离较大时仍会恢复跟踪。

## 关键函数和接口

| 接口 | 作用 |
| --- | --- |
| `VisionTextResult_Parse()` | 把 K230 文本帧转换成结构化目标结果 |
| `VisionError_FromTarget()` | 根据画面中心计算 X/Y 像素误差 |
| `VisualTrackController_Update()` | 用 PID、死区和加速度限制生成轴速度目标 |
| `VisualState_Update()` | 在 SEARCHING、TRACKING、HIT、LOST、FAULT 之间切换 |
| `HAL_UARTEx_ReceiveToIdle_DMA()` | 用 IDLE 事件接收不定长 K230 文本帧 |
| `PanViewUi_Refresh()` | 只刷新发生变化的 TFT 区域 |
| `PanViewUi_HandleTouch()` | 把触摸坐标映射为启动、停止和主题事件 |

## 本阶段的调试方法

1. 先区分视觉识别、UART 接收、控制计算、电机执行和屏幕刷新五条链路，不能看到电机抖动就直接改 PID。
2. 查看 `target`、`err_x/err_y`、`pan_speed/pitch_speed` 和视觉状态是否同步变化，判断抖动来自检测框、状态切换还是执行机构。
3. 用锁定进入阈值和锁定退出阈值分开设计，优先增加滞回，而不是盲目提高 PID 增益。
4. 对 DMA 启动记录返回值和 HAL 状态；回调里不能假设重启一定成功，失败必须留待应用上下文重试。
5. 现场日志必须记录本次测试的时间和文件版本。旧日志只能用于历史背景，不能作为最新复现的证据。
