# T07 双轴步进执行与实机调试复盘

- 日期：2026-09-04
- 分支：`feature/freertos-rearchitecture`
- 阶段状态：已完成板上实测，待长期运行验证
- 固件基线：`fec22b8`；T07 固件为包含本记录的后续提交
- K230 模型：本阶段未修改，具体模型提交哈希待补充

## 实验目标

把 T06 生成的 `MotionCommand` 交给独立的步进执行模块，使水平轴和俯仰轴能够根据视觉误差实际转动，同时加入人工零点确认、启停、速度过渡和双轴软件限位。

## 硬件与信号

- 控制器：STM32F407，运行 FreeRTOS CMSIS-RTOS V2。
- 执行器：两台 X42S 步进电机驱动模块。
- 水平轴 STEP：TIM4 Channel 1；俯仰轴 STEP：TIM3 Channel 4。
- STEP、DIR、EN 引脚沿用当前 CubeMX 工程配置。
- 电机电源与逻辑电源分开供电并共地，接线以已核对的工程配置和实机为准。

## 最终实现

1. `MotionTask` 发布最新一份 `MotionCommand`，单槽消息队列覆盖旧命令，不累计已经过时的速度。
2. `StepperTask` 每 10 ms 读取最新命令，只负责调用步进模块，不在任务函数中实现定时器换算和限位算法。
3. `panview_stepper.c` 独占 STEP、DIR、EN、TIM3、TIM4 和理论位置累计。
4. `panview_speed_ramp.c` 让实际速度逐步接近目标速度；反向前必须先减速到 0。
5. 复位后系统暂停且双轴失能。第一次按下 KEY_UP 时把当前位置记为双轴软件零点并开始跟踪；再次按下时暂停、停止脉冲并失能；下次开始会重新计算零点。
6. 运行中目标丢失、进入死区或触发限位时停止 STEP 脉冲，但保持电机使能和力矩。
7. TIM3/TIM4 更新中断只转发给步进模块，由模块按实际脉冲方向累计理论位置。

## 最终参数

| 参数 | 当前值 | 单位与说明 |
| --- | ---: | --- |
| 水平 P | 2.5 | `step/s` 每像素误差 |
| 俯仰 P | 2.5 | `step/s` 每像素误差 |
| I、D | 0 | 本阶段未启用 |
| 运动命令上限 | 800 | `step/s`，双轴上游共同限制 |
| 水平执行上限 | 820 | `step/s`，当前实际仍受上游 800 限制 |
| 俯仰执行上限 | 800 | `step/s` |
| 执行层速度变化量 | 60 | 每 10 ms 最多变化 60 `step/s`，约 6000 `step/s^2` |
| 水平位置范围 | -800 到 +800 | 脉冲计数，对应软件角度 -90° 到 +90° |
| 俯仰位置范围 | -800 到 +800 | 脉冲计数，对应软件角度 -90° 到 +90° |
| 定时器时钟 | 84 MHz | 当前 CubeMX 时钟树的 APB1 定时器时钟 |

角度只是根据理论脉冲数换算，没有编码器反馈。复位、手动转动、堵转或丢步后，理论位置会失去可信度，必须重新人工回中并按 KEY_UP 确认零点。

## 关键缺陷与定位过程

调试中曾把 STEP 定时器时钟按 HSI 的 16 MHz 计算，但 TIM3 和 TIM4 实际使用的是 84 MHz APB1 定时器时钟。因此实际脉冲频率变成命令值的：

```text
84 MHz / 16 MHz = 5.25 倍
```

这一错误在目标接近中心时表现为突然的大幅动作，容易被误认为 PID 或视觉坐标跳变。排查时先让电机脱离视觉闭环，以固定速度和固定方向运行，再比较命令速度、定时器配置和实际转速。固定速度仍明显不符，说明问题位于执行层而不是 K230 检测或 P 参数。

修正为 84 MHz 后，再按以下顺序恢复闭环：

1. 使用固定速度确认双轴方向和实际速度量级。
2. 加入速度过渡，确认启动、停止和反向没有速度突变。
3. 只使用 P 控制，从较小 P 值逐步增加，分别调节水平轴和俯仰轴。
4. 最后验证目标出现、目标丢失、到达死区、方向反转和软件限位。

## 为什么当前不需要 I 和 D

视觉目标会持续提供新的位置误差，云台只需要根据误差方向和大小不断修正。当前机械负载、速度范围、30 px 死区和速度过渡已经能让目标稳定停在允许范围内，因此 P 控制已满足本阶段目标。

- I 用于消除长期静差，但视觉框本身有抖动，积分可能累积噪声并造成到位后继续运动。
- D 用于抑制快速变化，但检测坐标存在帧间跳动，微分会放大这些变化。
- 在没有观察到必须由 I 或 D 解决的问题前，将二者保持为 0，控制逻辑更容易理解和调试。

## 验证结果

- 已实测水平轴和俯仰轴方向正确。
- 已实测目标移动时双轴能够跟随，目标到达中心附近后可保持稳定。
- 已实测双轴最大命令速度为 800 `step/s`，启动、停止和反向具有速度过渡。
- 已实测 KEY_UP 可以确认零点、开始跟踪、暂停失能和再次确认新零点。
- 已实测双轴软件位置限制为 `±800` 脉冲，即软件换算的 `±90°`。
- 已观察串口 `T07` 日志中的目标速度、实际速度、运行状态、位置和角度随运动更新。
- 已确认板载 LED 在实机运行中持续闪烁。
- 主机测试覆盖运动误差/速度计算和通用速度斜坡函数。
- 完整 STM32 工程已使用独立构建目录编译验证。

## 当前限制与下一步

- 软件限位依赖脉冲理论计数，不具备编码器闭环或物理限位开关保护能力。
- `MotionCommand` 和视觉结果采用最新值语义，尚未加入命令超时安全停机。
- 本阶段没有把 I、D 调到非零，也没有证明它们永远不需要；只有后续出现明确静差或阻尼需求时再重新评估。
- 下一阶段应继续补充 SafetyTask 的故障位、通信超时和独立停机路径。
